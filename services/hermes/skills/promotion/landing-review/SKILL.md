# Landing-page activation review

Produce an evidence-based private review and proposed copy. This skill grants
no deployment, publication, account, email or spending authority. Preserve owner
holds and treat proposed product changes as proposals rather than shipped work.

Inspect the available rendered page and observed journey using authorized
read-only evidence. Separate homepage reachability, working navigation, signup,
installation, first server join and first useful game action. Mark untested
steps explicitly; a screenshot or HTTP 200 does not verify activation.

Compare the page's headline, gameplay proof and primary action with the incoming
campaign's actual promise. Identify the earliest mismatch or unnecessary friction.
Prioritize comprehension, demonstrated value, clear prerequisites and an honest
first-session expectation before cosmetic button experiments.

Use a finding table: observed screen/step, evidence, likely user consequence,
proposed smallest change, confidence and verification method. Include accessibility
and mobile readability when evidence permits. Supply replacement copy for the
highest-impact issue, grounded in verified features and rights-cleared proof.

Review trust claims separately: ownership, Minecraft non-affiliation, reward
mechanics, requirements and support. Unresolved cross-server currency or reward
claims need current platform-guideline and architecture review before reuse.
Do not assert compliance, payout reliability or player popularity from surface
copy. Propose an activation event and a manual usability check; do not claim a
conversion uplift without matched observed data.
